## 报告中需要纠正或保留条件的结论

| 编号 | 结论与未按建议修改的原因 |
| --- | --- |
| H1 | 其他会话账本损坏确实会使 spawn 拒绝。但该账本参与跨会话写冲突保护，不能仅当作参考信息；直接跳过可能漏掉活动 writer。当前保留拒绝，损坏账本造成的可用性限制仍存在。自动隔离需要独立且可信的活动状态证据。 |
| M1 | 账本 reservation 和未绑定 marker 相加的现象成立，但没有关联证据时，它们也可能代表两个不同代理。不能仅凭数量假定同一实体。报告 T4 所称第二、第三个只读 spawn 均应放行也不成立：身份未确认时不满足三个已验证只读代理的前提。保留保守计数，异常载荷下并行度下降仍存在。 |
| M4 | Codey 崩溃可能留下 pending；仅按时间到期回落不安全，角色文件或 lease 可能已部分更新。现有保存/启动恢复会校验并重建完整配置。此次补充恢复诊断，未实现崩溃后的自动恢复。 |
| M6 | 全局锁和锁内读取存在，但报告没有真实并发压测证明发生超时。更改锁粒度涉及 SessionEnd 清理、共享状态和账本事务一致性，保留当前锁；性能问题需独立基准验证。 |
| L2、L3 | 当前调用图中有不可达状态分支，但枚举 match 仍需穷尽。换成 `unreachable!` 只会增加未来变更时的 panic 风险，没有修复功能缺陷，保留防御性分支。 |
| L4 | 当前生产 `parent_id` 均为 None，但字段仍参与持久化和遥测格式，不能仅凭构造点值恒空就删除。 |
| L5 | 没有发现生产代码写入 live 规则文件，但读取与 last-good 行为真实存在。没有产品契约证据支持删除手工规则入口，本次保留。 |
| L6 | 中文子串分类影响遥测，不参与授权；属于维护性问题，暂未重构所有拒绝结果类型。 |
| L7 | 当前实际工具集未提供 `agents.agent_status`。仅因规则分类包含这个名称，不足以证明当前用户可见工具被错误拒绝；未新增缺少协议定义的入口。 |
| L9、L10 | 60 分钟 Stop 绝对上限、跨会话冲突仅覆盖相同 runtime 均为当前设计限制，已补入维护文档；未放宽执行边界。 |
| L11、L12 | 重复 hash 和较长函数存在，报告中的函数长度、迁移逻辑等与当前版本不完全一致。不能把静态复杂度计数直接视为功能缺陷。 |

H2 的影响描述也需收紧：第一条反斜杠样例在 PostgreSQL 默认字符串语义下留下未闭合字符串，不能仅凭词法器返回 true 就断言 DROP 已成功执行；SQLite 对 `#` 的语义也不能直接等同于 PostgreSQL。此轮回归验证词法器拒绝这些结构，没有对真实数据库执行破坏性 SQL。自定义函数的副作用仍无法通过词法分析普遍证明，数据库只读账号继续作为实际权限边界。

## 性能与清理建议

- P1、P3：重复账本加载、规则加载和锁内 transcript 读取属实。按事件引入缓存上下文会改变持久化边界，暂不与本次正确性修复混合。
- P2、P7：不能仅按 24 小时或文件年龄跳过账本、清理会话。活动 reservation 没有可靠心跳，长任务可能没有近期更新时间。
- P4、P8、P9：属于微优化，没有独立修复价值；当前 Hook 事件为 7 个，报告写 8 次 trust hash 不准确。
- P5：mtime 与文件长度不能代替内容比较，同尺寸替换仍可能发生，保留原校验。
- P6：合并状态文件需要迁移和损坏恢复设计，本次不改。
- `ExecutionPhase::Failed` 在当前迁移实现中没有报告所称的统一转换，不能直接删除。单行转发函数仍有调用；结构字段相同也不代表状态语义可合并。未进行无功能收益的清理。

仓库中的 Hook/transcript 测试为构造数据，不能证明所有 Codex 版本的 session_id、transcript_path 与信任哈希契约均一致；这些外部契约仍待真实载荷验证。
