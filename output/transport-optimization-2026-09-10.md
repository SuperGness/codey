## 候选方案与选择

| 方案 | 收益范围 | 风险与结论 |
|---|---|---|
| 本地 HTTP/2 或 keep-alive | 本地 HTTP 请求连接开销 | 主要样本已经使用 WS，协议改造较大，本次不实施 |
| 缩短 WS 3 秒超时 | 握手超时并转 HTTP 的请求 | 可能把原本可以成功的 WS 连接转成更慢的 HTTP；不调整 |
| 原始 JSON 顶层改写 | 大上下文的本地序列化 | 普通 WS 转发前仅毫秒级，日志不足以证明收益；还需保证历史恢复后的字段一致性，不实施 |
| 复用 WSS TLS 配置 | 同服务端重复新建 TLS 连接 | 复用现有 rustls 会话缓存，改动小且可验证，选用此方案 |

## 实施与风险边界

- 原先 tungstenite 默认每次新建 TLS ClientConfig，连接间不能复用会话票据。现在进程内共享一个配置，使用 rustls 自带的有界、按服务端域名隔离的会话缓存。
- 保留当前 Mozilla 根证书来源、证书与域名校验、TLS 默认协议、连接超时、WS 消息内容及 HTTP 回退规则。0-RTT 保持关闭，避免请求重放。服务器拒绝票据时自动完整握手。
- 不跨进程持久化会话；第一次连接、已建立的 WS 长连接、HTTP/SSE、明文 WS 没有会话恢复收益。服务端必须提供且接受会话票据；TLS 1.3 恢复仍通常需要一次网络往返。
- rustls、webpki-roots 都已在依赖树中；此次只是声明直接使用，未引入新的库版本。

## 验证结果

- 独立公网探测只发送 TLS 握手及无认证 HEAD 请求，不发送模型请求。交替执行 8 次独立配置和 8 次共享配置；独立配置全部完整握手，共享配置首次完整握手，随后 7 次均恢复会话。
- 公网握手耗时波动较大，不能用这组小样本推断线上首字延迟下降。
- 本地固定证书 TLS 1.3 测试：完整握手 1233 字节，恢复握手 810 字节，握手数据减少 34.3%。该比例仅适用于此测试证书，不能外推为总传输量减少。
- 本地内存握手对照，交替各 200 次，debug 构建：完整握手 P50/P95 为 1330/1508 微秒，恢复为 1245/1423 微秒。覆盖双方 TLS 处理及独立配置构造，不含网络；收益约几十微秒，不能据此承诺用户可感知的提速。
- 回归验证覆盖共享配置身份、恢复握手、域名隔离、无效证书、域名错误、关闭 0-RTT、服务端重启后完整握手。
- 本地路由测试：218 通过，3 个按需基准忽略，0 失败。
